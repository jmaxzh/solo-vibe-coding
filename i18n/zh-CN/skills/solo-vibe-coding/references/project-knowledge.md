# 项目知识库规范

用于工程任务中定位、补充和维护项目知识，统一不同 Skill 的文档归属、存放与更新方式。以下路径相对正在开发的产品项目根目录；文件按实际内容需要建立。

## 确定文档位置

先查看项目已有的指令、README、文档入口及相关文档，沿用已经明确的目录、命名和格式。同类文档只有一套存放约定；缺少约定的类别使用下表默认位置。发现重复或矛盾时，结合内容、引用和当前实现确认主要维护位置，在任务范围内修正或说明差异。

| 内容归属 | 默认位置 | 保存什么 |
| --- | --- | --- |
| 项目使用入口 | `README.md` | 项目用途、启动与常用命令，链接到详细文档 |
| 知识库导航 | `docs/README.md` | 按主题链接现有文档，简述用途，避免重复正文 |
| 当前系统结构 | `docs/architecture.md` | 模块与边界、依赖、关键数据流、运行形态及当前约束 |
| 功能规格 | `docs/specs/<feature>.md` | 该功能的目标、范围、行为、必要技术约束与验收依据 |
| 重要架构决策 | `docs/adr/<nnnn>-<decision>.md` | 背景、选择、备选方案、取舍及后果；延续已有编号 |
| 业务术语 | `GLOSSARY.md` | 领域概念、精确定义和关系；有多个领域上下文时沿用项目既有映射 |
| 跨任务测试知识 | `docs/testing.md` | 有长期价值的测试策略、运行方式、测试数据约束和已知覆盖缺口 |
| 项目质量标准与检查入口 | `CONSTRAINTS.md` | 适用指标、阈值或基线、实际检查命令、运行时机、阻断规则与例外；引用工具配置与流水线 |
| 调研与实验档案 | `docs/research/<topic>.md` | 需要留存的方案调查、实验、验证和历史分析，标明结论的适用范围 |

已有 OpenAPI、JSON Schema、Protobuf 等接口定义或生成文档时，引用其主要源文件；spec 补充行为、错误与兼容性约束，减少重复维护字段定义。普通实现细节与可执行测试留在代码和测试中，知识库说明有复用价值的意图、边界和操作方法。

## 多个 Skill 共用文档

- 同一主题优先更新已有主要文档，其他文档通过链接引用。以功能、领域或系统主题命名，避免为每个 Skill 建立一套同义文档。
- 同一功能的产品需求与必要技术约束可以共存于同一份 spec。内容确需拆分时，以主题划分并相互链接，明确各自负责的内容。
- 上游 Skill 提供的默认目录、文件名与模板服从项目的存放约定；沿用同类文档的现有结构，将有用内容合并到相应位置。模板用于补充信息，不据此另建第二份同主题文档或重排无关内容。
- 一个任务使用多个 Skill 时，后续指导继续补充同一份相关文档。补充前读取现有内容，保留有效约束、取舍与限定条件，核对本次实际差异。
- 文档导航链接主要维护位置；新增、移动或删除已索引文档时维护相关链接。知识库很小时可先由项目 README 承担入口，内容增长后再建立独立导航。

## 内容应当表达什么

**功能 spec** 按实际复杂度组织，覆盖理解与实现该功能所需的信息：目标与范围、关键行为和场景、必要接口或数据约束、错误与边界、验收和验证依据。只写相关内容，避免空章节和重复粘贴代码。已有测试、接口定义和关联决策通过链接引用。

**架构说明** 描述当前系统；待实现方案与当前状态明确区分。重要选择的理由保存在 ADR，架构文档链接当前有效决策。

**ADR** 用于有真实取舍、需要长期理解且改变成本较高的重要决策，记录背景、决定、备选方案和后果。目录和标题沿用项目格式，缺少格式时以上述内容组织。决策改变时新增记录并标明替代关系，保留旧记录供追溯。

**术语表** 维护业务概念及含义，统一需求、代码和文档的用词；实现细节和功能规格回到对应文档。

区分已确认要求、当前实现和待验证构想。代码与测试可用于核实当前行为，需求表达预期；两者不一致时说明偏差和依据，结合任务意图处理。未知内容标明不确定性。

## 何时维护

- 任务改变功能行为、公共接口、重要约束、运行或测试方式时，与实现一起交付对应文档更新；有长期价值的新结论补充到相应主题。
- 普通说明直接更新，由版本控制保留历史。临时排查、候选比较和失败尝试通常作为本次任务反馈；需要完整留存时写入调研档案。
- 将确认的稳定结论提炼到使用说明、spec、架构或术语中，保留必要依据与关联决策。当前操作说明与约束应自包含，使用者无需阅读聊天记录或研究档案才能理解。
- 没有持久知识变化时，无需为了调用了某个 Skill 而新增文档。按当前请求范围维护相关内容，不扩展为全项目整理。

知识库规范约束的是文档存放与协作方式。当前任务采用哪些分析方法、需要哪些参考以及如何验证，由用户要求、项目条件与实际证据决定。
