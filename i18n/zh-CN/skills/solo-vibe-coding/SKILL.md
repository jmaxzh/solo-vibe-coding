# Solo Vibe Coding

为已有明确产品方向的独立开发者，按当前目标独立选择或组合专业指导，复用项目事实与已有实现，遵循项目约束完成交付并维护可复用知识。不探索创业方向。

## 结合项目条件应用指导

- 根据当前要求提供建议、评审或实现，沿用已知产品事实、品牌、审美、技术栈和代码，只补充影响本次任务的缺失信息。
- 视觉制作或外观调整前，先取得可查看的具体参考；复用已有认可的页面、组件或作品，缺少时先帮助查找。通过[视觉与交互](references/visual-interaction.md)选择对应的上游工作流。
- 处理任何需求，先复用已有成果；新增实现优先采用适用的成熟开源基座、框架、组件或模板，仅自行实现无法合理覆盖的部分。需要调研时使用 [search-first](https://github.com/affaan-m/ecc/blob/main/skills/search-first/SKILL.md)，按适配性、维护情况、许可证、兼容性和总体成本判断；调研深度与任务规模相称，复用仍有效的结论。
- 上游的默认步骤、模板与数量要求结合用户要求和项目条件使用；专业判断、方法和组合由模型依据实际任务决定。风格偏好服从用户和项目已有选择。
- 官网或多语言文案按目标语言、地区与受众习惯撰写，调整措辞、语气和行动提示，避免逐句直译。保持产品事实、能力边界、承诺与操作含义一致；先独立通读自然度，再对照核验信息。

技术实施以已确认的需求为输入，沿用其验收条件与项目约束。需求讨论与澄清属于独立任务，本流程承接其已确认结果。

1. **设计并实施技术方案。** 遵循必选的[技术方案流程与输出结构](references/technical-planning.md)，明确验收场景与预期结果。在任务授权内按[开发与质量](references/development.md)的工程纪律实施，期间继续执行项目已有的自动检查。
2. **对实际运行的实现进行真实验收。** 按[真实验收](references/development.md#真实验收)模拟用户完成任务，验证实际结果。通过后按其中的审查重构循环，依次进行非 bug 代码评审、行为保持的重构、每次重构后的针对性复验和再次评审，直至满足停止条件。

- 单独开展需求确认时，必须执行[需求与沟通中的 grill-with-docs](references/requirements.md#必选指导)；复用已有上下文与已确认结论，经用户确认未决事项后再推进实现。
- 涉及用户使用流程的需求与方案，必须说清用户旅程：谁在什么场景下，从何开始，经过哪些关键操作与系统响应，最终获得什么结果；交代影响完成目标的分支、异常与衔接。
- 其他问题与细节结合所用 Skill 和项目约定组织，表达清楚、连贯，详略与任务复杂度相称；在有助于理解时使用标题、段落、列表或表格，呈现重点及内容之间的关系。
- 实现方案（含缺陷修复、新增功能）对每个独立工作项说明工作量、风险及依据、假设与未知。工作量考虑改动、复用、联调与验证成本；风险考虑可能性、后果及必要应对。可用小／中／大工作量、低／中／高风险；简单任务简述，复杂任务按需分组或列表。

任何工程项目在启动或接手时，优先确定质量指标并建立自动检查，再推进功能实现和结构性重构。先读取已有标准、工具配置、测试与流水线，能够满足要求时直接沿用；缺少时按[质量指标与自动检查](references/quality-and-ci.md)补齐适合项目规模的可执行基线。托管平台或仓库条件不支持 CI 时，采用本地可重复运行的自动检查。后续任务遵守既有标准，只补充本次变更暴露的缺口，不重复建设。

首次远程读取前，读取并遵循[远程读取与发现](references/guidance-access.md)，按其中的原文、路径、版本和依赖规则取得选中指导。无须安装或注册技能，复用已读的同版本内容。

本指南未覆盖当前需求、候选失效或用户要求继续查找时，使用该文档中的[补充技能发现方法](references/guidance-access.md#发现补充技能)。工具或来源不可用时说明具体缺口，标明依据后完成仍可交付的部分。

## 依据实际结果交付并维护知识

内容依据真实产品与证据。只找网站时提供现成站点与适用用途；寻找具体案例时定位到原始页面、截图、组件源码或素材文件，动态效果提供可播放示例。交付状态以实际取得的文件、运行和验证结果为准。

工程任务按需定位项目知识，结合代码与测试理解事实和约束。涉及知识库读写时，读取并遵循[项目知识库规范](references/project-knowledge.md)，沿用项目已有约定，多技能共用主要文档；按任务范围维护稳定知识，需要留存的完整过程进入研究档案。

任务进行中，用户纠正设计判断或规范，或问题暴露了持久指导的缺失或错误时，主动读取并使用 [Reflect](references/project-knowledge.md#纠正触发的反思)。普通实现疏漏无需触发反思。
