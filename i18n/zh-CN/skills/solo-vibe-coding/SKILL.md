# Solo Vibe Coding

为已有明确产品方向的独立开发者，按当前任务选择并组合专业指导，遵循项目约束完成交付，并维护可复用的项目知识。不探索创业方向。

各任务可以独立进入；按当前任务读取相关指导与约束。

## 选择任务指导

按当前目标选择入口，按需组合范畴，复用项目事实、约束与实现。

技术栈指导补充实现方法，质量指导落实工程基线；两者按需组合，框架或质量设施问题也可独立进入。

## 结合项目条件应用指导

- 根据当前要求提供建议、评审或实现，沿用已知产品事实、品牌、审美、技术栈和代码，只补充影响本次任务的缺失信息。
- 处理任何需求，先复用已有成果；新增实现优先采用适用的成熟开源基座、框架、组件或模板，仅自行实现无法合理覆盖的部分。需要调研时使用 [search-first](https://github.com/affaan-m/ecc/blob/main/skills/search-first/SKILL.md)，按适配性、维护情况、许可证、兼容性和总体成本判断；调研深度与任务规模相称，复用仍有效的结论。
- 上游的默认步骤、模板与数量要求结合用户要求和项目条件使用；专业判断、方法和组合由模型依据实际任务决定。风格偏好服从用户和项目已有选择。

### 工程项目的优先事项

任何工程项目在启动或接手时，优先确定质量指标并建立自动检查，再推进功能实现和结构性重构。先读取已有标准、工具配置、测试与流水线，能够满足要求时直接沿用；缺少时按[质量指标与自动检查](references/quality-and-ci.md)补齐适合项目规模的可执行基线。托管平台或仓库条件不支持 CI 时，采用本地可重复运行的自动检查。后续任务遵守既有标准，只补充本次变更暴露的缺口，不重复建设。

### 读取原文与补足指导

首次远程读取前，读取并遵循[远程读取与发现](references/guidance-access.md)，按其中的原文、路径、版本和依赖规则取得选中指导。无须安装或注册技能，复用已读的同版本内容。

本指南未覆盖当前需求、候选失效或用户要求继续查找时，使用该文档中的[补充技能发现方法](references/guidance-access.md#发现补充技能)。工具或来源不可用时说明具体缺口，标明依据后完成仍可交付的部分。

## 依据实际结果交付并维护知识

### 核实交付状态

内容依据真实产品与证据。只找网站时提供现成站点与适用用途；寻找具体案例时定位到原始页面、截图、组件源码或素材文件，动态效果提供可播放示例。交付状态以实际取得的文件、运行和验证结果为准。

### 项目知识库规范

工程任务按需定位项目知识，结合代码与测试理解事实和约束。涉及知识库读写时，读取并遵循[项目知识库规范](references/project-knowledge.md)，沿用项目已有约定，多技能共用主要文档；按任务范围维护稳定知识，需要留存的完整过程进入研究档案。
