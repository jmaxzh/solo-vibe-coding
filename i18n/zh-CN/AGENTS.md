# 仓库指令

- 使用中文

## 项目目的

为已有产品方向的独立开发者组织按任务取用的专业指导。兼顾不同使用者的目标与项目约束，以实际帮助和使用负担评价改进。

## 交付物与制作过程

- 编写或更新可复用产物时，只保留服务其用途的能力、边界、操作方法和必要依据。对话记录、临时状态、候选取舍及纠错经过属于制作过程，不直接写成产物的运行规则。
- 将沟通中确认的要求转化为简洁、稳定的行为；避免把单次失败、阶段性条件或被放弃的方案固化为普遍禁令。
- 需要完整留存调研、历史评分或验证记录时，独立保存于研究或维护文档；可执行产物及其运行时引用不依赖这些档案。
- 交付前检查：首次使用者能否不读聊天记录理解并使用产物；只解释“我们如何做到这里”的文字应移出。研究报告、决策说明、审计与变更记录等以过程为内容的产物，按其用途及用户要求保留。

## 项目维护

- **作用范围**：通用维护规则写入 `AGENTS.md`，技能共性行为写入技能包，需沉淀的项目或任务要求写入对应规格或任务说明。个人偏好设为通用默认前，核对适用范围和成本。
- **目标核对**：沿用已有背景与文档，明确本次结果、约束和成功依据；重要选择或反馈后复查方案与验收。只澄清会实质影响结果的信息缺口。
- **结构维护**：遵循芭芭拉·明托的金字塔原理，做到结论先行、以上统下、归类分组、逻辑递进。
- **变更评估**：任何修改后，依据实际差异比较前后版本，说明明确改善、对应项目目标和证据；区分实现检查与用户效果证据。检查相关能力、约束和成本是否退化，并披露未验证项。确保符合帕累托改进原则：至少一个相关维度获得明确改善，其他相关维度均不退化。评估与评审深度均与变更规模相称，呈现形式按需要选择。
- **独立评审**：维护变更交付前，使用新上下文的只读评审代理。提供用户原始需求与已确认要求、适用指令、修改前后版本、差异和必要验证证据，让评审者先独立判断，涵盖目标一致性、要求作用范围及收益与成本证据，再核对变更评估。修正查实的退化与遗漏，并复核受影响部分。交付时说明评审结论与证据缺口；存在退化或关键证据不足时不判定通过，无法执行独立评审时明确标记未完成。

- 中英文保持对应。忠实翻译内容，保留能力、默认选择、要求、边界、来源链接及结构。技能行为按用户要求变更；发布说明放在仓库 README 中。
