# Project initialization

Use when starting or taking over an engineering project to prepare a repeatable local environment and applicable automated checks. Read project instructions, the README, dependencies and lockfiles, configuration examples, startup scripts, existing quality standards, and pipelines first. Reuse valid work and prepare the engineering foundation according to actual gaps.

1. **Confirm necessary engineering choices.** Retain confirmed requirements and existing technology choices. When a missing choice affects preparation, assess it using [architecture and technical design](architecture.md), following its default stack when unspecified. Resolve material requirement or scope gaps through [requirements clarification](requirements.md).
2. **Prepare the local environment.** Follow [local environment and debugging preparation](development.md#local-environment-and-debugging-preparation) for runtimes, dependencies, environment variables, and services actually needed. Run applicable migrations and development-data initialization; verify service connectivity and a critical application path. Reuse native or containerized workflows, preserve existing local data, and distinguish first-time initialization from repeatable startup.
3. **Establish the quality baseline.** Use [quality criteria and automated checks](quality-and-ci.md) to define standards appropriate to project size. Reuse or fill gaps in check tools, the local entry point, and applicable automation, and verify that checks work. Establish this baseline before implementing features or making structural refactors.

Following [project knowledge conventions](project-knowledge.md), maintain necessary setup, startup, shutdown, and check instructions in existing documentation, creating documents according to actual content needs. Report actual preparation, startup, and verification results and missing prerequisites. Find existing foundations, Gin examples, and Compose setups in [development references](resources/development.md). Continue with the [technical planning workflow](technical-planning.md) and [development and quality](development.md), retaining the environment and standards established here.
