# Mobile UX Design Principles

Use the [shared principles](../SKILL.md#shared-principles) and entry rule R2.3 for selection; clauses use the entry document’s levels and P bases.

| Clause | When | Requirement | Criterion | Basis |
| --- | --- | --- | --- | --- |
| **M1** | The keyboard opens | Keep the active field, errors, and necessary controls visible or reachable by scrolling. | The keyboard does not make these task elements unreachable. | P4 |
| **M2** | Choosing mobile navigation and back behavior | Follow target-system conventions. [Source context](sources.md#navigation-and-back-behavior) | Navigation behavior agrees with the target system. | P3 |
| **M3** | Providing mobile navigation actions | Distinguish going up a level, closing temporary UI, and switching primary areas. [Source context](sources.md#navigation-and-back-behavior) | These actions retain distinct meanings. | P3 |
| **M4** | Returning to browsing | Preserve filters, scroll position, and other browsing state as needed for return. [Source context](sources.md#navigation-and-back-behavior) | The browsing context needed to resume the task is restored. | P3 |
| **M5** | Adapting mobile navigation | Adapt to available space and the target platform. [Source context](sources.md#navigation-and-back-behavior) | Navigation fits both constraints. | P2 |
| **M6** | Adapting mobile navigation | Keep core tasks reachable. [Source context](sources.md#navigation-and-back-behavior) | Core tasks remain accessible after adaptation. | P2 |
| **M7** | Adapting mobile navigation | Keep the logical relationships among core tasks recognizable. [Source context](sources.md#navigation-and-back-behavior) | Navigation still communicates those task relationships. | P2 |
| **M8** | The target is mobile web | Read [web principles](web.md) under R2.5. | Mobile and browser rules are available. | P1 |
