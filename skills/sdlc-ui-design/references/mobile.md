# Mobile UI Design Principles

First read the [shared principles](../SKILL.md#shared-principles). This table uses the entry document’s rule format: the required result is the criterion. Each Basis names an L1 principle in that document.


## Usage

| ID | When | Required result (criterion) | Basis |
| --- | --- | --- | --- |
| MB1 | selecting mobile rules | must select for the target device, OS, and grip. | P2 |
| MB2 | targeting mobile web | must also read [web principles](web.md). | P2 |

## Platform principles

| ID | When | Required result (criterion) | Basis |
| --- | --- | --- | --- |
| MB3 | placing frequent actions | must keep them within reach for the target device size and grip. | P3 |
| MB4 | proximity could cause accidental activation | must separate actions with serious consequences from frequent actions. | P3 |
| MB5 | placing mobile interface content and controls | must avoid system bars, cutouts, and system gesture regions. | P3 |
| MB6 | designing native iOS or Android component visuals | must prefer the target platform’s recognizable component visuals. [Source context](sources.md#native-component-visuals). | P2 |
| MB7 | expressing brand choices in native components | must use the platform’s supported theming and customization mechanisms. | P2 |
| MB8 | styling native iOS or Android text | must map text to the platform’s text styles or roles. [Source context](sources.md#native-typography). | P2 |
| MB9 | rendering native iOS or Android text | must respect the user’s system font-size setting. | P3 |
