怎么开始

从你自己的项目开始。

改善官网、重做界面、交付第一版，或准备发布。装好 Skill，选一段贴近自己情况的需求，继续做手边的项目。

打开你的编程助手给当前项目加上 Skill选一件你现在想完成的事打开成果，自己试一试

打开你的编程助手

在你用来做项目的助手中打开一个项目文件夹。助手需要能修改文件并访问网络。下面的主路径以 Codex CLI 或 IDE 扩展为例。

还没用过编程助手？按官方指南安装并打开 Codex CLI。

给当前项目加上 Skill

把下面这段话发给 Codex，让它帮你检查环境并安装。

复制到编程助手中
请为当前项目安装适用于 Codex 的 Solo Vibe Coding。
先检查是否有 Node.js 22.20+ 和 npm；如果缺少，请给我具体的准备步骤。
然后执行：
npx skills add jmaxzh/solo-vibe-coding --skill solo-vibe-coding --agent codex --yes
告诉我安装是否成功，以及如何在当前助手中选择这个 Skill。

在 Codex CLI 或 IDE 扩展中，输入 $ 选择 solo-vibe-coding，也可以打开 /skills。如果列表里还没有新 Skill，重启 Codex 后打开同一个项目。

我使用 Claude Code 或其他助手

Claude Code 用户在项目文件夹运行下方命令，再输入 /solo-vibe-coding 并接上自己的需求。其他助手可以用通用安装命令，按提示选择正在使用的助手。

终端
npx skills add jmaxzh/solo-vibe-coding --skill solo-vibe-coding --agent claude-code --yes
终端
npx skills add jmaxzh/solo-vibe-coding --skill solo-vibe-coding
我希望自己在终端安装

准备好 Node.js 22.20+ 和 npm，在项目文件夹运行下方命令。默认安装到当前项目，添加 -g 可以跨项目使用。

终端
npx skills add jmaxzh/solo-vibe-coding --skill solo-vibe-coding --agent codex --yes

选一件你现在想完成的事

先完成上方安装，再发送与你任务对应的需求。把方括号换成自己的项目信息。 前往安装步骤

将这段需求发给 Codex；也可以先在正在使用的助手中选择已安装的 Skill，再发送相同的需求描述。Claude Code 用户把开头的 $ 调用改为 /solo-vibe-coding。

产品和目标用户：[补充说明，或指向现有项目]。
现在的问题：别人能看到功能，却看不出为什么值得用。
请帮我找准具体的用户痛点，选择能体现用途的演示，再落实成文案和电脑、手机都能用的官网。只使用真实能力和证据。
沿用现有项目和合适的成熟方案。说明重要选择，做出能打开试用的版本，告诉我实际检查了什么，还有什么需要验证。

把已经想清楚的产品，先做出一版给人用。

功能做了一堆，用户还是走不完一个流程。

复制到编程助手中
使用 $solo-vibe-coding，帮我做出这个产品的第一个可用版本。
产品方向：[做什么、给谁用、他们需要完成什么任务]。
已有项目和约束：[补充现状]。
请先梳理一条完整的核心使用流程，明确哪些功能可以以后做。优先评估现有代码和成熟开源方案，再实现缺少的部分。
会影响用途、费用或访问范围的选择，说明后让我确认。建立适当检查，交付能打开试用的版本、运行方式和真实验证结果。

拿到成果后，自己确认

  • 用户能否从头到尾完成核心任务？
  • 是否清楚怎么运行、有哪些限制、验证了什么？

把已经能用的产品，发给真正要用它的人。

本地能跑，交给别人之前心里还是没底。

复制到编程助手中
使用 $solo-vibe-coding，帮我发布这个已有产品。
项目、现有托管和目标用户：[补充说明]。
先检查并沿用已有部署方式，涉及费用和访问范围时让我确认。
准备发布和可用的回退方案，在我授权的范围内执行。发布后打开实际公开地址，检查关键使用路径。
交代发布版本、网址、检查结果和剩余问题，把操作说明保存在项目中。

拿到成果后，自己确认

  • 希望使用它的人，能否打开链接并完成主要操作？
  • 是否知道检查了什么，以及出了问题怎样恢复？

打开成果，自己试一试

让助手告诉你怎样打开成果。根据刚才选的任务，确认这些基本问题：

  • 是否解决了你一开始提出的问题？
  • 实际打开，走完主要使用路径。
  • 涉及页面时，也在手机上试一试。
  • 问清实际验证了什么，哪些还需要确认。
