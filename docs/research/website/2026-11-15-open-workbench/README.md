# 官网新版：打开的产品工作台

本文件记录发布前的本地预览验收。新版双语完整页面与现有功能路径已实现，实际画面、工程检查与独立只读审查已完成，未留必须修复问题。GitHub Pages 发布已完成，见 [发布与线上核验](publication.md)。

## 设计理由

希望访客感到：一个人做产品，也能有清楚的下一步。主导概念是“打开的产品工作台”，从项目的用途和安装路径出发自主构图，没有使用现成网站、模板、参考图或历史作品作为新版设计依据。

暖白纸面承载阅读，墨蓝强调专业指导，钴蓝标记主要行动，浅绿标记可检查的交付目标。原创 HTML/CSS 插图把需求页、方法页和结果条分层放置，用轮廓、折角、厚度、投影和尺度反差建立主体；网页标题、说明、按钮和图中文字均为真实 HTML 文字。插图明确标为工作方式示意。

首页依次解释产品定位、任务用法、具体困难、使用步骤、实际记录与可操作示例、安装和常见疑问。深色任务工作区、开放式编号叙事、浅蓝步骤区、错落的证据卡和深色安装区形成章节节奏。内页共享色彩与导航，保留阅读和工具操作所需的结构。

## 变更评估

比较基准为本次修改前的 Git 提交 `cbf2ded9eb5e96e037b9b85c74bfa9802c7531e8`，在隔离目录使用相同的已安装依赖构建。比较检查以 [实际 diff](change.diff) 为准。

| 维度 | 修改前 | 修改后 | 证据与判断 |
| --- | --- | --- | --- |
| 主视觉与产品的关系 | 装饰金属主体，另设任务说明 | 需求、方法、交付三个层次组成原创主体 | 图示含义和产品流程直接对应；易懂程度仍待真实用户验证 |
| 交互与路径 | 双语任务、安装、案例、报价、六个历史任务锚点 | 保留相同能力，并在手机直接呈现主导航 | 浏览器回归与静态链接检查；用户价值不能仅由测试推定 |
| JavaScript | 17,274 B | 13,963 B | 减少 3,311 B（19.2%），移除未继续使用的 Canvas/指针增强组件 |
| 全站静态产物 | 955,842 B | 869,680 B | 减少 86,162 B（9.0%）；清理已不用的金属主视觉资源 |
| 依赖与服务 | Astro 静态站、原有字体和报价逻辑 | 沿用 | 未增加依赖、字体、后端或外部服务 |

测量见 [build-metrics.json](build-metrics.json)。视觉方向按本次自主设计要求更换，不能宣称所有人更喜欢新版。手机导航增加一行占用，以便直接访问现有三条主路径；主要操作仍在首屏内。资源、依赖、既有路径和功能的已测维度未发现退化；实际用户偏好、理解和转化效果尚无证据。

## 运行与复现

官网需要 Node.js 22.23.4+。在仓库 `website/` 下，已有依赖时执行：

```sh
npm run build
npm run preview -- --port 4391 --ignore-lock
```

首次运行先执行 `npm ci`。端口被占用时选择空闲端口，并采用服务器实际输出的网址。网站保留 `/solo-vibe-coding/` 项目路径。

```sh
npm run validate
PLAYWRIGHT_PORT=4391 PLAYWRIGHT_CHANNEL=chrome npm run test:e2e -- --workers=4
node ../docs/research/website/2026-11-15-open-workbench/capture.mjs
```

`capture.mjs` 的 `PREVIEW_ORIGIN` 可指定其他预览源地址；没有本地 Chrome 时按官网 README 安装 Playwright Chromium，并相应调整浏览器选择。本地预览仅供本机访问；生产站点的发布与线上核验见 [发布记录](publication.md)。
