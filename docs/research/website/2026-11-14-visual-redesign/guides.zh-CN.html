使用场景

你现在，想做成哪件事？

找一个接近自己目标的场景，复制需求并补上自己的情况。可以让助手帮助梳理步骤、推荐做法。

做一个新东西加一个功能改善外观和体验修好一个问题发给别人使用把产品介绍清楚
做一个新东西

一个你一直想要的网站或小工具。

说明它要做什么、给谁用，让助手推荐一个适合先做出来的小版本。

可以打开试用的第一版，以及具体使用方法。

你可以确认什么

它是否做到了你想要的事？你是否知道怎样使用？

加一个功能

让已有的工具，多做一件有用的事。

描述想增加的行为，助手查看项目情况，推荐合适的接入方式。

复制到编程助手中
使用 $solo-vibe-coding，给我的报价工具加一个下载按钮。
我希望把当前数字下载成表格软件能打开的明细，保留现有外观。
请推荐做法、完成实现，并核对下载的数值。

先拿到什么

已经接入现有项目、可以实际操作的新功能。

你可以确认什么

新操作是否能完成？原来的功能是否仍然能用？

改善外观和体验

把已经能用的移动 App，做到愿意拿出去给人看。

功能都做好了，界面还是一股模板味。

一位开发者用 Claude Code 做完移动 App，却不满意普通的界面。反复要求重设计、提供参考截图，得到的仍主要是换颜色。

  • 把“好看”变成明确方向：用具体参考确定适合产品与用户的视觉层级、字体、间距和交互选择。
  • 改到实际的核心页面：保留现有功能和技术，让同一套视觉规范贯穿真实页面，落实成可操作的实现。
  • 用真实内容试一遍：检查主要操作、小屏幕、长内容，以及相关的空白、加载和错误状态。
复制到编程助手中
使用 $solo-vibe-coding，重新设计这个已有移动界面。
App、目标用户和主要操作：[补充说明]。
功能已经能用，但界面普通，反复说“好看一点”主要只改变了颜色。
请用具体参考提出合适的视觉方向，并落实到真实的核心页面。保留现有功能、品牌与技术；需要改变时说明理由。
交付能打开试用的版本，检查真实内容、小屏幕和重要交互状态，说明哪些还没有验证。

先拿到什么

明确、统一的视觉方向；已经实现的核心页面；真实手机交互的检查结果

你可以确认什么

主要操作是否容易找到，并且能完成？ 手机上能否容纳真实内容，处理重要状态？

修好一个问题

修好视频通话，原来好用的功能也继续好用。

修好一个 Bug，又弄坏一个原来的功能。

一位 Cursor 用户遇到这样的循环：修复访客黑屏时，助手反复破坏已经正常工作的背景虚化和视频处理。新的修复，又带来了新的问题。

  • 先让问题能重现：复现失败的通话操作，弄清相关媒体流和状态边界，再开始修改。
  • 把修复控制在必要范围：结合排错与架构指导找到原因，沿用现有实现，保留已经正常工作的行为。
  • 把该保留的功能再走一遍：检查访客画面、背景效果和核心通话流程，把可重复的检查留给下一次修改。
复制到编程助手中
使用 $solo-vibe-coding，修好这个已有视频通话应用。
问题：[失败的操作、预期结果、实际结果和报错]。
要保留的功能：[例如访客画面、背景虚化、录制]。
先复现问题，定位原因和受影响的模块边界，再做必要的修复。沿用项目已有实现与检查。
交付能打开试用的版本，验证原来的失败操作和相关功能，说明未验证项，把有用的回归检查留在项目里。

先拿到什么

能复现、能核对的修复；继续正常工作的原有功能；可以重复执行的回归检查

你可以确认什么

访客能否看到画面，并正常切换背景效果？ 原有通话功能是否仍然正常，检查能否再次执行？

发给别人使用

把差最后一步的 Web App，交给别人真正使用。

Demo 都做好了，最后一步却一直做不完。

一位没有编程基础的 UI/UX 设计师，反复卡在应用、数据库、登录、环境变量和部署之间。界面能生成，却迟迟没能成为完整的线上应用。

  • 选适合项目的成熟基础：结合现有项目、费用和访问需求评估方案，接通缺少的部分。
  • 走完一条真实使用流程：接好登录与数据，明确访问边界，检查从第一次操作到保存结果的完整过程。
  • 核对真正发布的版本：按你的授权发布，打开实际网址检查主要任务，留下部署与回退方法。

准备可用的发布和回退方案，在我的授权内执行。打开真实公开网址检查，交代验证结果和剩余问题。

目标用户能否登录、保存结果，再次打开时找到数据？ 公开网址是否可用，是否知道验证了什么、出问题怎样恢复？

把产品介绍清楚

把已经做好的产品，带到真正可能使用它的人面前。

产品做了几个月，却连第一批用户都没有。

Inslytic 的创始人发帖时，SDK、控制台和引导流程都已上线，但仍没有用户。社交发布、人脉联系和免费测试，都没让他分清问题出在触达、定位还是需求。

  • 先弄清卡在哪一步：结合公开用户信号和现有使用路径，区分没人看到、介绍不清、首次使用困难，还是需求本身较弱。
  • 让合适的人看懂用途：选择具体用户和任务，把真实能力变成清楚的表达、相关的演示和可用的试用入口。
  • 把第一轮推广准备好：准备适合渠道的内容和小范围触达计划，明确要观察的反馈。发布由你决定。
复制到编程助手中
使用 $solo-vibe-coding，帮这个已有产品触达第一批用户。
产品、目标用户、当前官网和已经尝试的推广：[补充说明]。
结合实际证据，区分触达、定位、首次使用困难和需求较弱等问题，不默认继续加功能。
选择具体用户任务，基于真实能力制作演示，改善表达和试用入口，准备适合相关渠道的内容。
说明应观察什么反馈。在任何发布或对外触达前，先把材料给我审阅；不承诺用户数量或收入。

先拿到什么

具体的用户与用途；看得懂的演示和试用入口；能执行、能观察反馈的首轮推广

你可以确认什么

目标用户能否看懂用途，并顺利完成第一次试用？ 能否观察到问题出在表达、入口，还是缺少使用理由？
