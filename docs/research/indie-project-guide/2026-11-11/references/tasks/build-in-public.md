# Build in public

用于用户主动要求公开开发、写开发日志、解释设计取舍、准备社交内容、发布素材或评估小工具传播。用户认可 build in public，但不据此自动发帖、定时运营或增加整个增长流程。

用户可能没有完整产品与用户，也可以分享真实探索、原型、视觉实验、选择依据、实现难点和阶段成果。先依据当前内容与受众选择表达，技术日志的读者与产品购买者是否重合是判断问题，不是必须先做用户研究的前置任务。

## 选择

| 当前任务 | 候选 |
| --- | --- |
| 单条帖、线程、社交表达、个人语气、素材复用 | social |
| 主题方向、内容组合、可检索与可分享内容 | content-strategy |
| 用户要求发布计划或某次产品/功能发布 | launch |
| 评估某个免费小工具是否适合作为传播入口 | free-tools |
| 明确建立长期公开实践、边界和节奏 | samber 的 build-in-public，可选低采用度备选 |

## 素材如何配合

同一个真实原型可按当前请求衍生出页面演示、交互录屏、封面、信息图或短视频。文字看 [文案](positioning-copy.md)，静态素材看 [图片](images.md)，视频看 [视频指南](video.md)。用户只要求其中一种时，其他形式作为可选建议，不自动全部生成。

参考包可包含一个主要视觉参考、局部截图、图标家族与具体动效源码。按任务说明参考对象的构图、排版或节奏；已有品牌和个人语气持续沿用。
