# 官网测试与验证

官网以静态内容、双语对应、公开路径和关键交互作为验证重点。质量门槛见 [CONSTRAINTS.md](../CONSTRAINTS.md)，命令在 `website/` 执行。

## 本地检查

```sh
npm ci
npm run validate
npx playwright install chromium
npm run test:e2e
```

`check` 验证 Astro 与 TypeScript，`build` 生成生产产物，`verify` 对实际 HTML 和文件运行检查；`validate` 串联前三项。Browser 测试由 `playwright.config.ts` 自动启动已有产物的预览服务器。

## 覆盖范围

| 风险 | 检查方法 |
| --- | --- |
| 路由或资源遗漏项目路径 | 解析所有产物内链和资源，按真实项目 URL 定位文件 |
| 锚点失效、重复 ID | 检查各页面 ID 与跨页锚点目标 |
| 语言切换丢失主题 | 元数据双向对应检查与实际浏览器切换 |
| 元数据遗漏或重复 | 检查标题、摘要、canonical、Open Graph 图片与 JSON-LD |
| sitemap 不完整 | 对照所有内容页面，确认网址存在且不含 404 |
| 脚本增加阻断阅读 | 在关闭 JavaScript 的浏览器上下文阅读示例并导航 |
| 目标入口与复制失效 | 首页到完整首次任务、旧场景锚点、实际剪贴板与拒绝权限后的手动复制 |
| 可用示例计算或下载错误 | 独立预期金额核对、分级舍入、负数/空值/超范围、零值/大数、CSV 内容与 BOM |
| 维护内容混入用户网站 | 产物中检查本仓库维护 docs 和工作流链接，保留普通 GitHub / 许可入口 |
| 手机横向溢出 | 以手机视口检查每类页面的文档宽度 |
| 可检测无障碍问题 | 桌面和手机运行 axe，严重与关键问题阻断 |
| 体积持续增长 | 构建产物文件大小预算 |

新增文章时同步登记 `src/data/posts.ts`，保持双语 slug 对应，并让类型、静态产物及浏览器检查覆盖新内容。静态验证不会请求每一个外部链接；外部来源的内容、许可与可用性仍需维护者核对。

## 检查工具的有效性

更改验证脚本后，应在可回退的构建目录中注入一个已知违规，例如不存在的本地链接，确认命令非零退出；恢复文件后再运行正常检查。不要修改源码或减弱标准来消除预期失败。

## 目标用户体验验证

工程检查与产品效果分别记录。真实目标用户需要能理解用途、找到接近自身目标的场景、准备助手并安装，在完整需求引导下得到可打开的成果，再继续提出修改。

安装命令可以在隔离临时项目中验证，检查 Codex 的 `.agents/skills/solo-vibe-coding/` 和 Claude Code 的 `.claude/skills/solo-vibe-coding/` 包含完整技能文件。该检查不等同已验证助手生成结果，更不能替代真实用户首次使用观察。

未进行目标用户试用时，明确保留理解成本、首次成功与提效效果的证据缺口。可操作示例只证明该功能实际存在，不提供任何任务都能自动完成的保证。

## 人工与生产检查

预览时观察桌面和手机排版、长命令、焦点、触控、减少动态效果与内容可读性。自动化不能覆盖所有视觉判断或全部辅助技术。

发布操作与回退方法见 [官网 README](../website/README.md)。发布后核对 GitHub 工作流、实际页面、样式和 sitemap。搜索引擎收录、AI 引用、真实用户性能与实际安装量需要另有数据来源。
