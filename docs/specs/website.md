# 官网需求与设计规范

官网服务有明确制作目标、但没有完整技术判断力的人，帮助他们理解 Solo Vibe Coding 的用途，并在自己的 AI 编程助手中推进到可用成果。维护者使用仓库知识库管理项目，两种读者的入口与内容分别组织。

## 用户目标与主要路径

用户能描述想做的网站、小工具或功能，可能不清楚如何拆解、选方案、实现、验证或发布。官网从目标与可见成果进入，专业方法由编程助手按任务选用。重要取舍用用户能理解的效果、费用与访问范围说明。

用户已有编程助手时，官网需要具体说明：做这件事可能卡在哪里，Skill 为助手提供什么帮助，以及希望交付什么。按任务选择专业指导、优先复用合适已有工作、适当工程检查和项目约定是指令事实；是否更快、更少返工或减少专业提醒需要比较证据。

主要路径为：识别想做的事与具体困难 → 理解 Skill 如何帮助助手 → 明确交付目标 → 安装 Skill → 延续所选任务发送完整需求 → 打开并试用成果 → 提出下一次修改。

网站提供产品说明、浏览器示例和上手内容；制作用户自己的项目发生在其编程助手中。示例不代表对所有任务、耗时或自主完成程度的保证。

## 页面与内容

| 页面 | 内容与行为 |
| --- | --- |
| 首页 | 从成果目标进入；修复循环、移动界面、Demo上线、首批用户四类外部场景分别呈现目标、困难、具体帮助、交付目标和原始讨论来源；提供安装入口并回答成本与效果边界等疑虑 |
| 真实任务 | 同一收藏工具的CSV导出和新会话追加筛选导出；实际使用的指导、项目结果、比较方法、成本与限制；独立可下载起始项目与两轮需求 |
| 实际示例 | 可操作的报价计算器、明细下载、用户可检查的结果、制作自己版本的完整需求与安装入口 |
| 怎么开始 | 以 Codex CLI/IDE 为一条明确主路径；可复制的环境检查与安装请求；Claude Code 和手动安装按需展开；首页所选任务链接到对应需求、验收要点，不强制改做统一示例 |
| 使用场景 | 做新东西、加功能、改善界面、修复问题、发布分享、介绍产品；代表场景沿用首页的困难、帮助、需求与验收；各场景保留原锚点 |
| 最新更新 | 展示新增可用成果、用户收益与下一步使用方式；保留原文章网址，并编辑为适合用户阅读的内容 |
| 404 | 返回有效首页，不参与索引 |

顶部导航提供使用场景、如何帮助和开始使用；场景和旧页面保留原URL与六个场景锚点，历史执行记录及报价工具在页脚提供入口。首页代表案例来自公开社区问题。GitHub、许可证与更新入口位于页脚。项目维护知识库、ADR、内部研究和 CI 档案通过仓库维护入口查阅，不成为官网文章或导航的阅读目标。

Skill 帮用户保留其项目背景和重要选择的能力，以“后续修改可以接着做”表达；这与维护 Solo Vibe Coding 自身的知识库用途不同。

## 可用示例

报价计算器使用用户输入的工时、单价、额外费用和预留比例，输出小计、预留金额与总额。数值改变时更新结果，非法或遗漏输入给出提示并停用下载；可下载带 UTF-8 BOM 的 CSV 明细。

金额按分计算并舍入，以保持页面和下载一致。默认示例随语言采用 USD/50 或 CNY/300 的单价，工时均为12，预留10%，无额外费用；币种在页面明确显示，不进行汇率换算。全部数据在浏览器计算，不新增后端或分析服务。

报价示例是实际可用的功能成果，不用来证明Skill的增量效果。真实任务案例只报告当前模型与条件下观察到的结果，不能把维护者任务观察写成真实用户试用。网站不展示未测量的提效、用户数量、转化或排名。

## 语言、兼容与视觉

默认英文，中文使用 `/zh-CN/`，均在 `/solo-vibe-coding/` 下。保留已有页面地址与六个场景锚点；语言切换保持当前主题。两种语言保持功能、边界与内容对应，示例货币采用明确的本地化显示。

首页采用浅蓝渐变向浅色页面过渡的视觉：居中标题、清楚的主次按钮、宽幅助手使用示意，随后以四个痛点、三步使用、真实内容、安装和 FAQ 组织页面。宽松版心、细边框、克制阴影与一致圆角形成连贯层级。首页的导航、页脚与色彩变量限定在 `body.homepage` 下；阅读与操作内页保留暖纸色视觉，避免首页改版改变其内容密度和操作反馈。沿用自托管 Manrope、中文系统字体与 IBM Plex Mono，不增加字体或运行依赖。后续延展到内页时，按页面用途迁移颜色、字阶与组件，并分别核对双语、桌面、手机和交互状态。

首屏以原创助手界面示意呈现「具体任务 → 现有编程助手按任务使用 Skill 专业指导 → 本次交付与检查目标」。明确标注使用方式示意，不能作为已执行的结果；制作发生在用户自己的编程助手中。原生单选控件切换四类任务，默认展示改善产品界面，内容来自共享任务数据。关闭 JavaScript 时，示意和对应任务的开始链接仍可操作；启用脚本时，导航、首屏与安装区的开始入口、刷新及语言切换共同延续所选任务。四个痛点始终可读，并保留专业方法和公开讨论来源；原帖作者不作为客户或成功案例。设计卡片可展开第三方界面参考，标明非执行结果。实际执行记录与可操作报价示例独立展示，分别标注证据性质并进入完整内页。指南继续使用已有任务参考，六个原锚点保持有效。

现成素材以自托管图片和轻量组件呈现，保留作者、原许可和必要的修改说明；公开源码分发范围与网站使用范围分别核对。设备样机使用原作者提供的成品样式；交互组件按既有 Astro 技术适配，不因选材引入额外框架。安装终端显示真实、完整、可复制的命令；首页直接显示完整命令，指南的可选输入动画仅为演示，不显示未经执行的安装成功记录。

中英文共享产品事实、功能、安装命令、费用、证据和边界，分别按读者习惯成稿，允许标题长度、句式、表达和排版不同。中文优先使用自然、具体的用户语言；英文采用自然的产品表达。完整检查导航、按钮、任务说明、文章、错误信息、图注与替代文本，避免用字段对应代替语言质量检查。

首页采用自然、具体的用户语言，保留成果目标、任务困难、具体帮助、交付目标和开始使用的叙事。原生单选控件切换四类任务，鼠标、键盘及关闭 JavaScript 时均可操作；界面参考与目标明确标为示意，不冒充原作者已使用本 Skill 的结果、本 Skill 的交付截图、客户证言或对照数据。报价成果和收藏导出记录独立保留，不承担首页代表案例。

动效用于首屏入场、任务切换和安装命令演示，内容默认可见。四类任务通过原生单选控件支持触控、键盘与读屏，关系图和详情均预渲染为HTML。持续动画提供暂停方式并保留偏好；遵循系统减少动态效果设置，触屏不依赖悬停。图片预留宽高，首屏关系图使用HTML与CSS，任务详情图片按需加载，不引入第三方 3D 运行时。

上手页用任务参数和锚点延续首页场景，需求和验收内容预渲染为 HTML。启用脚本时聚焦所选任务，安装往返、刷新、历史导航与语言切换继续保留；关闭 JavaScript 时完整呈现各任务需求，用普通锚点定位，避免把所选任务替换成默认任务。

保留旧上手任务参数与锚点`requirements`对应的新产品首版需求，与完整指南共用内容；新代表案例的调整不改变既有任务的目标。

报价示例的制作入口携带`quote`任务，延续该工具的完整需求、检查点与安装步骤；保持刷新、语言和历史导航时的任务连续性。

## 交互与无障碍

- 目标入口使用普通链接，场景和完整需求预渲染为 HTML。
- 报价示例由脚本增强。无 JavaScript 时显示初始结果、公式和启用说明，输入保持禁用，避免展示不会更新的假交互。
- 复制成功提供文字与读屏反馈；权限失败时选中原文，支持手动复制。
- 核心导航、语言切换、上手步骤、需求示例与 FAQ 在关闭 JavaScript 时可读可用。
- 输入有标签和范围，结果可读屏感知；页面提供语义标题、跳到正文、清晰焦点与减少动态效果支持。

## SEO 与 GEO

每页静态生成正文，提供独立标题、摘要、自身 canonical、双向 hreflang、分享图片与适合页面的结构化数据。sitemap 包含全部真实内容页，排除404。

产品定义、标题、FAQ 与案例一致说明为现有Agent增加什么指导，区分指令、观察与效果，并如实交代编程助手与工具条件。案例静态呈现真实日期与验证范围。结构化数据反映网站、页面、作者、文章和开源 Skill，不编造评分或效果。抓取与索引遵循已有项目域名方案；根目录 robots.txt 的规则仍需实际核对。

## 验收边界

工程验收检查静态产物、内链与锚点、双语、计算与下载、错误处理、键盘、手机、无 JavaScript 和可检测无障碍问题。上线以 CI 成功及公开页面实际响应为依据。

产品验收另外观察目标用户能否理解用途、选择适合自己的场景、沿默认路径完成首次制作，以及减少多少专业判断负担。没有实际用户试用时，不把工程检查当作产品效果证明。

视觉与语言验收覆盖所有页面类型的双语、桌面和手机并排对照，核对品牌一致性、图示是否表达具体任务、各语言完整路径是否自然。目标用户能否复述图示、理解用途和完成安装，需真实试用另行验证。
