# 官网需求与设计规范

官网帮助已有明确产品方向的独立开发者理解 Solo Vibe Coding 的用途，在自己的编程助手中安装并按任务使用专业指导。

## 用户目标与主要路径

主要路径为：了解能力 → 选择任务 → 安装 Skill → 发送符合本次范围的需求 → 检查交付结果 → 继续修改。六类任务可以独立进入，也可以只做需求、环境准备、技术方案或只读评审，不探索创业方向。

按任务选择指导、复用已有工作、适当工程检查和保留项目约定属于指令事实。更快、更少返工或效果领先需要实际比较证据，不能由指令存在或官网测试通过推断。

## 页面与内容

| 页面 | 内容与行为 |
| --- | --- |
| 首页 | 品牌定位与装饰光环、六类能力入口、三步使用方法、六步工程交付方法、完整安装命令、费用与边界 FAQ |
| 开始使用 | 以 Codex CLI/IDE 为安装主路径；Claude Code 与手动安装可展开；更新、版本核对、十二个任务需求、交付检查、继续修改和排障帮助 |
| 任务指南 | 按需求、视觉、初始化、技术交付、发布、获客六类组织十二个通用需求，说明交付目标和检查点，链接到上手页的同一任务 |
| 404 | 提供英文与中文首页入口，不参与索引 |

默认英文，中文位于 `/zh-CN/`；所有路径位于 `/solo-vibe-coding/` 下。公开页面为六个内容页与一个共用 404。导航提供任务指南、交付方法和开始使用；页脚提供相应入口、GitHub、许可和视觉素材来源。

首页通过使用步骤和工程交付方法说明工作方式。完整工程路径为：承接确认需求、调研复用、评估与设计、实现和持续检查、运行中模拟用户验收、评审精简与复验。只做需求、参考或评审时按所选范围交付。

通用任务需求直接说明目标、项目背景、交付范围和检查条件。能力说明和请求中的交付目标不代表实际执行结果或效果承诺。

## 任务与安装连续性

指南与上手页读取同一份需求和检查点，六类入口按现有任务 ID 定位。每份指南的开始链接携带任务参数与锚点；安装往返、刷新、历史导航及语言切换保持所选任务。无有效选择时默认展示需求澄清。关闭 JavaScript 时全部需求可读，普通锚点可用。

安装主路径提供环境检查与安装请求，命令完整、可复制。更新沿用原来源、目标助手、项目或全局范围、复制或链接方式，核对本地修改与固定版本。版本核对依据助手实际读取的文件、同名副本及完整包来源，不能以安装成功替代。

视觉任务先取得可查看的页面、截图、设计稿或图片，动效与视频使用可播放参考；缺少时先协助寻找。按产物检查实际页面、图片或视频，交付适用的文件与源文件，说明工具、访问、费用和验证缺口。

## 视觉与交互

保留电影感深色首页：大字定位、原创金属光环、冷蓝光轨和暖橙按钮。能力、交付、安装和 FAQ 的层级与色彩延续首屏；内页使用既有暖纸色。首页主题不影响内页。

沿用自托管 Manrope、IBM Plex Mono 和中文系统字体。装饰图不是界面或执行成果。文字默认可见，手机按内容重排，不截断主要文字、不劫持滚动。

动画提供暂停并保存偏好，遵循系统减少动态效果；Canvas 离屏、文档隐藏时停止循环，绘制上限 30fps。关闭脚本保留静态装饰与所有核心内容，触屏不依赖悬停。

复制提供文字和读屏反馈；权限失败时选中原文。原生 details 承载 FAQ 和可选安装说明，链接锚点能进入折叠内容。提供语义标题、跳到正文、清晰焦点，核对手机与键盘操作。

两种语言保持能力、安装、费用和边界一致，分别自然成稿，检查导航、按钮、需求、FAQ、图注和替代文本。

## SEO 与 GEO

每页静态生成正文，提供独立标题、摘要、自身 canonical、双向 hreflang、分享图片与真实结构化数据。sitemap 覆盖全部有效内容页，排除 404。

结构化数据描述网站、页面、作者和开源 Skill，与可见内容一致，不包含虚构评分或效果。根目录 robots.txt 按实际响应核对；维护知识、ADR 和研究不作为用户官网入口。

## 验收边界

工程检查覆盖确切页面清单、内链与锚点、双语、复制、任务连续性、键盘、手机、无脚本、动画和可检测无障碍问题。移除的页面与资源不进入产物，旧地址返回 404。上线核对同一提交的 CI、Pages 部署及实际响应。

目标用户是否理解用途、选择合适任务和完成首次制作，需要真实试用；工程检查不能证明产品效果。质量门槛见 [CONSTRAINTS.md](../../CONSTRAINTS.md)，页面范围依据见 [ADR 0015](../adr/0015-focused-website-content.md)。
