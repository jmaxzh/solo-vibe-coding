# ADR 0006：以现有Agent的增量指导和真实任务证据组织官网

- 状态：已采用。用户在阅读定位与证据方案后明确要求实施。
- 日期：2026-11-13
- 部分替代：[ADR 0005](0005-user-outcomes-and-audiences.md)的首屏报价工具及主要案例安排。
- 延续：既定目标用户、双语、GitHub Pages、轻量静态工程、上手路径和用户/维护入口边界。

## 结论

官网明确 Solo Vibe Coding 为现有编程助手提供什么额外指导：按任务选择专业方法与资源、结合现有项目优先复用、建立适当工程检查、保留后续修改需要的项目约定。以实际启用Skill的任务展示这些指导如何进入工作，并分别说明指令事实、观察到的行为和仍未证明的效果。

## 依据与选择

用户指出普通Agent也能制作报价工具，单个可用成品不足以证明安装Skill的价值。采用 April Dunford 的定位组件确定直接使用同一Agent的替代方案，用价值主张画布连接产品特征、用户负担与证据，用Test Card预先确定比较与验收。

首屏明确“给已有Agent增加一套专业工作方法”，主入口指向两轮真实任务；报价工具保留原URL和功能，作为次级成果体验。公开案例呈现实际操作、相关理由、任务结果、用量/时间与限制；完整日志、评分器、源快照和维护决策留在仓库研究区。用户可下载独立起始项目，无须读取维护档案。

首个案例采用同一收藏工具的CSV导出和新会话筛选导出，使用相同模型配置、业务需求、起始项目、权限、预算与验收。读取上游指导和安装准备属于成本，普通Agent也可能完成相同工作；没有证据时不主张速度、质量或专业补救优势。

## 代价与边界

新增真实截图、案例与用户可下载的项目，增加静态资源和双语维护成本；不新增网站后端或浏览器运行依赖。公开文案中的数据由已审查证据复制到网站专用数据文件，不在运行或构建时读取研究档案。

实验中共同环境故障应保留原结果，再登记同等条件修正后的新批次。少量维护者任务观察不能代表真实目标用户、实体手机、Windows Excel或一般Agent的效果。案例的局限与额外成本随结果一起说明。

重要决定与验收依据可追溯；用户使用网站与安装Skill仍不依赖本ADR或研究记录。Skill本身的行为未因官网改版而调整。
