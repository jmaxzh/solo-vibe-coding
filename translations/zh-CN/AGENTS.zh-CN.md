## 语言与来源

- `skills/` 中的英文内容是唯一可安装技能版本，定义行为和约束。不新增运行时语言选择或可被发现的中文 `SKILL.md`。
- `README.zh-CN.md` 和 `translations/zh-CN/` 仅为开发者维护译文，每份译文标明英文来源。翻译入口使用 `SKILL.zh-CN.md` 和 `AGENTS.zh-CN.md`。
- 修改英文规则、条件、示例或引用时，在同一次变更中同步中文。中文提案先落实到英文源，再同步译文；差异以英文为准。保留标识符、命令、配置键和协议名称。
- 运行脚本及其测试只在所属英文技能目录维护。翻译文档，不翻译或复制代码；该政策不限制用户对话和脚本输出的语言。

## 技能组合与分发

- 文档与指令设计规则仅在 `sdlc-instr-doc-design` 维护。工作流处理文档时按运行环境实际名称及命名空间加载该技能；操作和排障说明仍只按需复用相应章节。
- 无法取得必需依赖资料时，报告缺项，仅暂停依赖部分；不静默忽略规则，也不自动安装技能。
- 推荐五项技能的完整套件。工作流的最小支持组合包含 `sdlc-workflow` 与 `sdlc-instr-doc-design`，不承诺仅安装工作流即可取得所有文档规则。
- 不创建公共规则目录、规则生成副本或自定义依赖安装器。直接维护插件清单，并校验身份、版本和许可证一致。
- 各技能保留 MIT 声明以支持单项安装；根许可证变更时同步固定副本。
- 交付前运行 `python3 -B scripts/validate.py`、分发测试和 CC Connect 现有测试；CLI 可用时检查原生清单与安装清单。区分静态检查、本地实际加载、模型行为与目标机器部署。
- 准备本地变更和发布包的授权不等于推送、上传、提交审核或公开发布授权。

## worktree 优先的开发策略

仅适用于 `/Users/zhangjin/rich-workspace/my-dev-skills`、其注册 Git worktree，以及 `../my-dev-skills-worktrees` 下来源已验证的任务副本。根据 worktree 关系或副本来源判断项目归属，不以名称、远端 URL 或父路径相同为依据；归属不明确时，先澄清再应用规则。

- 主工作区：`/Users/zhangjin/rich-workspace/my-dev-skills`；远端：`origin`；基线：`main`。所有相对存储路径均从主工作区解析。每项任务或备份使用新的、不冲突的 `<unique-id>`。
- 每项任务前检查主工作区 Git 状态和 worktree，获取远端基线，同步为干净的 `main`，且 HEAD 等于本轮获取的 `origin/main` 精确提交。仅落后时使用快进；覆盖本地改动或独有提交前验证下述备份。获取远端、同步或备份验证失败时，停止项目修改。
- 干净判定仅忽略根 `.cc-connect/` 下的未跟踪运行数据；没有其他改动或未跟踪文件时，主工作区视为干净。保留该目录及其内容，不自动删除、迁移或提交。已跟踪改动、其他路径及 HEAD 同步要求仍须检查。
- 主工作区仅用于读取、同步和必要恢复。每项任务在独立 worktree 或副本中开发、测试和提交；目录从本轮已验证远端提交创建，保存于 `../my-dev-skills-worktrees/<unique-id>/`。
- 占用须有其他任务正在修改主工作区，或其他 worktree 检出 `main` 并妨碍同步的证据；确认后停止操作并报告证据。会话工作目录、空闲进程和只读访问不算占用。
- 覆盖原状态前，将全部工作文件（含忽略文件）、索引、HEAD/refs 和完整 Git 元数据备份到 `../my-dev-skills-backups/<unique-id>/`。沿 Git 目录指针取得所需共享元数据和外部对象，记录源路径、提交、时间和任务。验证文件清单、内容哈希和不依赖实时源仓库的提交可恢复性。diff、stash 或 `.git` 指针不足以替代备份；不自动删除备份。
- 清理临时任务目录前，检查未提交改动、相对最新获取的 `origin/main` 的未合并提交和任务依赖。仅在无须保留且不影响其他任务时删除；无法确定当前基线或检查结论时保留。不得删除主工作区或归属不明的嵌套仓库。
