# 工作区策略模板

替换 `{{PARAMETER}}`，移除代码围栏及本说明，并按所选层级调整适用范围的表述。保留 `<unique-id>`，要求每项任务或备份使用新的、不冲突的目录。

```markdown
## worktree 优先的开发策略

仅适用于 `{{MAIN_WORKSPACE}}`、其注册 Git worktree，以及 `{{WORKTREE_ROOT}}` 下来源已验证的任务副本。根据 worktree 关系或副本来源判断项目归属，不以名称、远端 URL 或父路径相同为依据；归属不明确时，先澄清再应用规则。

- 主工作区：`{{MAIN_WORKSPACE}}`；远端：`{{REMOTE}}`；基线：`{{BASE_BRANCH}}`。所有相对存储路径均从主工作区解析。
- 每项任务前检查主工作区 Git 状态和 worktree，获取远端基线，同步为干净的 `{{BASE_BRANCH}}`，且 HEAD 等于本轮获取的 `{{REMOTE}}/{{BASE_BRANCH}}` 精确提交。仅落后时使用快进；覆盖本地改动或独有提交前验证下述备份。获取远端、同步或备份验证失败时，停止项目修改。
- 干净判定仅忽略根 `.cc-connect/` 下的未跟踪运行数据；没有其他改动或未跟踪文件时，主工作区视为干净。保留该目录及其内容，不自动删除、迁移或提交。已跟踪改动、其他路径及 HEAD 同步要求仍须检查。
- 主工作区仅用于读取、同步和必要恢复。每项任务在独立 worktree 或副本中开发、测试和提交；目录从本轮已验证远端提交创建，保存于 `{{WORKTREE_ROOT}}/<unique-id>/`。
- 占用须有其他任务正在修改主工作区，或其他 worktree 检出 `{{BASE_BRANCH}}` 并妨碍同步的证据；确认后停止操作并报告证据。会话工作目录、空闲进程和只读访问不算占用。
- 覆盖原状态前，将全部工作文件（含忽略文件）、索引、HEAD/refs 和完整 Git 元数据备份到 `{{BACKUP_ROOT}}/<unique-id>/`。沿 Git 目录指针取得所需共享元数据和外部对象，记录源路径、提交、时间和任务。验证文件清单、内容哈希和不依赖实时源仓库的提交可恢复性。diff、stash 或 `.git` 指针不足以替代备份；不自动删除备份。
- 清理临时任务目录前，检查未提交改动、相对最新获取的 `{{REMOTE}}/{{BASE_BRANCH}}` 的未合并提交和任务依赖。仅在无须保留且不影响其他任务时删除；无法确定当前基线或检查结论时保留。不得删除主工作区或归属不明的嵌套仓库。
```
