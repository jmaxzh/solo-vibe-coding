# worktree 优先的开发策略

维护策略指令；配置时不执行其中的 Git、备份或清理操作。

## 依赖

通过实际注册名称和命名空间加载已安装的 `sdlc-instruction-optimization`，或从发现的安装位置读取入口及相关资料。不可用时报告缺失依赖，暂停相关写入，继续独立检查，不自动安装依赖。

单独安装时需要这两项技能；完整插件已包含两者。

## 选择位置

用户尚未指定时，让其选择：

1. **项目级**：仓库根目录的 `AGENTS.md` 或 `CLAUDE.md`。
2. **用户级**：`~/AGENTS.md` 或 `~/CLAUDE.md`，仅约束本项目及其任务目录。使用用户主目录，不使用工具配置目录。

复用已有文件及同层级规则源，保留文件名大小写。两份文件独立存在且规则源不明确时询问；均不存在时创建 `AGENTS.md`。

根据运行环境证据或当前官方文档检查用户级文件是否自动加载。不支持或未验证时，说明需要显式加载或引用；保留所选位置，不修改其他文件来启用加载。

## 确定参数

读取适用指引、Git 配置和 worktree 信息。依次按用户选择、项目约定、明确的 Git 证据确定参数，无法确定时询问。不假定当前目录或分支就是主工作区或基线。

| 参数 | 含义 |
| --- | --- |
| `MAIN_WORKSPACE` | 主工作区的规范化绝对路径 |
| `REMOTE` | 获取基线所用远端 |
| `BASE_BRANCH` | 主工作区应保持检出的基线分支 |
| `WORKTREE_ROOT` | 默认 `../<project-directory-name>-worktrees` |
| `BACKUP_ROOT` | 默认 `../<project-directory-name>-backups` |

存储路径以 `MAIN_WORKSPACE` 为起点解析，包括用户主目录指引和任务 worktree 场景。用户明确选择其他存储位置时，替代默认值。

## 写入策略

- 按文件语言或用户指定语言生成[模板](references/workspace-rules.md)内容，保持章节自足，保留适用范围和约束。
- 更新已有章节，保留无关规则和其他项目内容。修订所选层级内的直接冲突；跨层级冲突或阻碍写入的冲突，报告后由用户决定。
- 检查参数替换、范围、路径和引用。报告修改的文件与章节、所选层级、未决冲突和加载证据。
